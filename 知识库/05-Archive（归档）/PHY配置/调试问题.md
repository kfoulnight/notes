Linux 内核和网卡驱动的统计信息（`/sys/class/net/` 和 `ethtool -S`）是“不会说谎的证人”，能告诉你数据到底有没有发出去、有没有收回来。

对端链接到windows下需要把防火墙关闭掉，或者临时放行ping

可以查看到对端的mac地址
arping -I end0 -c 3 192.168.1.2


cmd管理员运行
netsh advfirewall firewall add rule name="允许Ping" protocol=icmpv4:8,any dir=in action=allow

连通性测试：

1：ethtool <接口名称>     ethtool end0

![[Pasted image 20260904112213.png]]

link detected 必须为yes 否则检查硬件连接

2：
2.1确认开发板能够将目标ip解析为目标MAC 
ip neigh show dev end0  
如果目标ip地址的mac地址为本机接口的mac地址，则数据会自环，需要删除  
2.2使用apring进行探测 （arping 是二层协议，只要网卡和交换机正常，对端有ip 就必回）
arping -I end0 -c 3 192.168.1.2
如果没有回复，就查看对端ip是否设置正常
2.3通过a



rping可以拿到正确的MAC地址，可以用静态apr 固定下来避免解析干扰
ip neigh add  192.168.1.2 lladdr a0:ad:9f:51:7b:50 nud permanent dev end0

3:验证数据流
确认网卡硬件是否真的在收发数据包  
cat /sys/class/net/end0/statistics/tx_packets
cat /sys/class/net/end0/statistics/rx_packets


4.传输层/协议层（TCP/UDP） 
当ping不通但是apring通时，证明是ICMP被防火墙拦截。
timeout 2 bash -c "echo > /dev/tcp/192.168.1.2/22" && echo "Port 22 is OPEN (IP层通)" || echo "Port 22 is CLOSED/TIMEOUT"
如果是Port 22 is CLOSED/TIMEOUT 就在win下开启ping（可能就是win 防火墙导致的但是22端口很可能用于ssh所以close很正常）
cmd管理员运行
netsh advfirewall firewall add rule name="允许Ping" protocol=icmpv4:8,any dir=in action=allow
再进行ping操作
